# 纯代码制片总纲（Code2Video Methodology）

> 适用场景：**零实拍、科普图解、数据故事、产品与 UI 动效演示、AI/SaaS 控制台、风格化 2D/3D 短片**，以及为实拍口播补足高信息密度视觉切片。

---

## 一、 核心原则：`frame(t) → image` 纯时间函数

纯代码视频的本质是一个确定性纯函数：第 `i` 帧画面完全由时间戳 `t = i / fps` 唯一决定。任何翻车几乎都源于以下 4 个反模式：

1. **未先定规约直接写动画** → 文案与画面错位、风格前后割裂。
2. **依赖墙上时钟（Wall Clock）或实时帧率 (`requestAnimationFrame`)** → 无头截图速度不均时，动画忽快忽慢甚至漏帧。
3. **随机数与物理积分写在渲染帧内** → 画面粒子/线条高频闪烁抖动，且跳过渲染会算错状态。
4. **“我写了函数就等于画面对了”** → 交付后实看像素才发现字太小、主体过偏、阴影压黑或动作瞬移。

### 确定性四大工程铁律
- **时间唯一输入**：所有位移、透明度、相机角度与形变均写成 `t` 的闭式表达式或分段缓动组合，严格经 `window.seek(t)` 驱动。
- **固定随机数种子（PRNG Seed）**：粒子初速、背景噪点、纸张纤维必须在初始化阶段用固定种子生成并缓存，帧内禁止调用非确定随机函数。
- **物理与粒子预烘焙（Pre-bake）**：流体、弹跳、群落或粒子演化按固定时间步长 `dt` 预先算完并存入帧表；渲染 `t` 时仅做线性插值采样。
- **视频素材内嵌铁律（严禁直播 `<video>` Seek）**：在 HTML/Canvas 渲染内嵌视频窗口时，无头浏览器异步 `video.currentTime` 极易黑帧或错帧。必须先用 `generate_code_broll.extract_clip_sequence()` / FFmpeg 按目标帧率与显示尺寸预先抽成 JPG 序列帧，预加载完成后在 `seek(t)` 内按 `Math.floor(localT * fps)` 精确绘制。

## 三、 标准工作流：`Brief → SPEC + STRUCTURE → 渲染 → 双重核验`

### Step 1：把简短创意凝固为 `SPEC.md` + `STRUCTURE.md` + `00_code_spec.json`
使用 `scripts/code_video_spec.py --init-spec` 初始化并在编码前核定 6 大契约（`--validate-spec` 强制校验）：
1. **画幅与容器规格**：分辨率（竖屏默认 `1080×1920` / 横屏 `1920×1080`）、帧率 `30fps`（严禁奇数宽高）、目标时长及 `±10%` 允许误差、总帧数 `round(dur * fps)`、声音需求。
2. **Verbatim 文案白名单（Exact Copy）**：上屏固定文案逐字按序锁定，**未写入契约的价格、参数、指标与宣传词一律禁上屏**。
3. **事实台账（Fact Ledger）**：所有数值、日期、公式及物理常量标注出处与单位。
4. **传入素材清单**：每份素材的实测 `ffprobe` 规格、裁切时间窗及禁用操作（如 Logo 禁改色拉伸、产品图禁重绘失真）。
5. **美学与布局约束**：精确 Hex 色板（复用本仓 6 大母版 / 24 套风格谱）、商业字体、安全区留白（竖屏保留 `y ∈ [1180, 1468]` 双通道字幕洁净带）与主视觉占幅比（关键元素高度 ≥ 画幅 `1/3`）。
6. **分幕时间表（`STRUCTURE.md`）**：按秒列出每一幕的视觉状态、主事件与转场手法，要求每数秒有明确视觉状态演化（避免单一效果空转到底），并名列 2–3 个最易翻车的风险点及可测检查项。

### Step 2：技术栈按内容匹配（不盲从单一工具）
- **矢量卡片 / UI 界面 / 动态字体 / SVG 路径**：HTML + CSS + Canvas 2D / SVG，经 `scripts/capture_html_video.mjs` 无头确定性抓帧编码（最快且排版保真）。
- **高频数据图表与标准商业补镜**：`scripts/generate_code_broll.py --backend auto`（HTML 优先，缺浏览器自动降级 Pillow + `pipe:0`）。
- **精密数学几何与公式推演**：Manim（先渲染独立镜头再并入主轨）。
- **产品立体展示与空间穿行（3D）**：Three.js，导出前必须**按 `1/30s` 步长沿相机路径及周围安全球做射线检测（Raycast）防穿模**——碰到实体必须修轨道，不可靠压缩 `near` 裁切面糊弄。
- **角色或生物动作表演**：先做剪影（Silhouette）与骨骼落脚约束——足部着地支撑阶段世界坐标锁死（步频由位移 `distance / stride` 驱动，拒绝滑步）；关键动作满足“预备—发力—缓冲回正”，静态停顿不超过 `1.5s`。

### Step 3：帧耗时预算与分片编码
- 正式渲染整片前，先用 `capture_html_video.mjs --frames 3` 在最繁忙帧测单帧耗时。
- 经验预算：**单帧尽量 `≤ 300ms`**；若纯软件 NumPy/Pillow 对全幅做逐像素掩膜循环超时，应立刻将绘制迁移至 Canvas 2D / WebGL 或预烘静层缓存。
- 长片段支持按 `--start` 与 `--frames` 分片并发渲染同源 HTML，再通过 `ffmpeg -f concat -safe 0 -c copy` 无损拼合。

## 四、 视觉取证三板斧：Cold Read + Action Strips + `VERIFY.md`

严禁用“代码写了”替代“像素看到”：
1. **Stills First（高危单帧先看）**：先抽开篇、峰值动作与复杂构图静态帧。
2. **Cold Read（陌生人盲读法）**：审图时先遮蔽源码意图，按第一次见的路人口吻记录：“第一眼主视觉是什么？能认出物体轮廓吗？占幅多大？屏幕字最小多少像素？对比是否压得住底图？”再反过来对照 `SPEC.md`，**认不出就判定未完成**（例如代码意图画烤羊排却读成褐色色块，视为 FAIL）。
3. **Action Strips（动作连拍条 `10_action_strips.jpg`）**：静止单帧看不出瞬移、弹跳卡顿与字幕闪切。统一产出前 3 秒 `0.2s` 步长与切点前后 `0.15s` 步长连拍条逐格排查。
4. **`VERIFY.md` 像素证据链**：逐条核对必检项，每条只认“时间点 + 屏幕坐标/像素观感描述”，拒绝空泛自证。

## 五、 高频翻车速查表

| 常见故障 | 根本原因 | 工程解法 |
| :--- | :--- | :--- |
| 成片播放加速/掉帧抖动 | 动画读取 `Date.now()` 或依赖 `rAF` 步长 | 全部改为 `window.seek(t)` 驱动闭式 `t` 函数 |
| 首帧空白或字体回退豆腐块 | 字体/图片未解码就置位截图 | 等 `await document.fonts.ready` 与 `img.decode()` 后再置 `window.READY=true` |
| 背景噪点/笔触高频闪烁 | 每帧重新调随机扰动 | 初始化阶段离屏一次性绘制并缓存贴图 |
| 内嵌视频黑屏或慢 3 帧 | 无头环境中动态播放 `<video>` 并反复 seek | 用 `extract_clip_sequence` 预抽 JPG 序列按帧索引绘制 |
| 主体太小或被底字幕压住 | 凭感觉估坐标而非测盒模型 | 主体 ≥ 画幅 `1/3`，文案实测 `textbbox` 且避开 `SUBTITLE_SAFE_ZONE` |
| 角色像贴纸或滑步 | 无剪影辨识度 / 足端未锁世界坐标 | 先验纯黑剪影辨识度，支撑脚锁世界坐标按位移步进 |
| 3D 镜头穿过物体内部 | 相机轨迹穿入模型碰撞体 | 每 `1/30s` 路径球形射线防穿模，重调曲线控制点 |
