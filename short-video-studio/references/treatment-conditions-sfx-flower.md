# 音效 / 花字的「出现条件」：触发条件 · 调用原则 · 作用域 · 可印证指标

> 用户实测原话（2026-11-24）：**「这一版的音效过于密集，感觉是没有任何缘由就出现，风格模版应该好好
> 抽象下这些音效、花字之类的是要在什么情况下才会出现，调用的原则是怎样，作用域又是怎样，而不是
> 无脑的硬植入。所有的 24 个风格模版也都要反思。风格模版是要围绕着怎样可复用而成立，复用后又从
> 哪些点可以印证这就是对应的风格。」**
>
> 旧 `step6_packaging.py` 只有「密度 + 最小间隔」，音效被铺在每一个切点上（style_21 实测 41 条），
> 花字更是倒挂——它拿音效 cue 当花字锚点，于是"有音效就有花字"。本文档把这两类处理的**出现条件**
> 从 24 套源草稿里反推出来，落成规则表、代码门禁和可印证指纹。

---

## 一、触发条件（这条音效 / 这张花字凭什么出现）

### 1.1 音效：必须挂到一个可观测锚点

真值来源 `forensic/style_edit_grammar.json` + `draft_content.json` + `assets/sound_vibe/sfx_truth/`。
对每套风格的**每一条**音效 cue，量它到四类锚点的偏移，取最近的一个作为"它凭什么响"：

| 触发类型 | 锚点 | 判据 | 长什么样 |
|---|---|---|---|
| `cut` | 主轨切点 | 偏移 ≤ 120ms | 换镜同时"呼"一声 |
| `flower` | 花字出现 / 退出点 | 偏移 ≤ 120ms | 花字砸上屏时配一声 |
| `line` | 字幕换行点 | 偏移 ≤ 120ms | 换句时轻轻点一下 |
| `beat` | BGM 节拍网格 | 偏移 ≤ 80ms | 踩拍点的击打 |
| `free` | 无 | 四类都不贴 | 编辑随手放的（**额度由风格实测比例决定**） |

**关键结论：24 套里 20 套的音效 100% 可归因，其余 4 套（style_07/15/17/20）也有 85%~93% 可归因**
（余下的是这类"综艺感"风格真实存在的随手 accent，用 `max_free_per_min` 单独配额，不放开成常态）。

**"切点"必须是结构性切点。** 源草稿的切点只有一种，而 pipeline 的切点带类型。实测 41 条里有 22 条
贴在 `stress`（口播中段重音微切）上、4 条贴在 `bgm_beat`（等分节拍微切）上——这正是听感里
"没有任何缘由就响一声"的来源。规则：`stress` / `bgm_beat` 不算切点理由，`sentence_start` /
`pause_start` / `pause_end` / `bgm_downbeat` / `keyword_accent` 才算。

### 1.2 花字：必须有出处，并且落在转折上

对每张花字（= 非字幕文字轨上的每一段文字）量它跟"同期人声"的关系：

| 触发类型 | 判据 | 可执行性 |
|---|---|---|
| `number` | 文案里有带量级的数字（三百万 / 两百平 / 99元 / 1993年） | ✅ 内容自证，任何风格都允许 |
| `chapter` | 章节/条目转折：标题式序号（一、/第一/首先/最后），或段落落地后的长镜（≥1.8× 中位镜长），或人声正在播报条目 | ✅ |
| `keyword` | 文案能在同期人声里逐字找到（含前后 ±3s 的句子） | ✅ |
| `line_echo` | 整句回声：花字就是这句字幕 | ✅ |
| `cut` | 花字正好落在切点上（画面换、字跟着换） | ✅ |
| `card` | 同一时刻 3 层以上不同文案 = 文字面板/清单 | ❌ pipeline 不做多层版式，不冒用 |
| `fragment` | 单字碎片（逐字弹字的中间态） | ❌ 不冒用 |
| `free` | 既无字面出处，也不贴任何锚点（编辑自行改写/总结） | ❌ **不上屏** |

24 套花字可归因率中位数 **0.89**；最低的 style_08（0.26）是因为该套字幕轨与人声不同源
（字幕是受访者原话、花字是讲师总结），字面不可溯——这类风格只复制能溯到出处的部分，
差额记在 `evidence.unexecutable_share` 里，**不假装能自动生成**。

**"数字"是唯一不受风格配额限制的触发**：只要人声真说了数字，把它压上屏不需要风格许可
（仍受字数、停留、密度、作用域约束）。因为这是内容自证的——任何风格都不会因为"说了一个数字"
而不能上花字。

## 二、调用原则（判定顺序与优先级）

一条音效 / 一张花字要过五道闸，任何一道不过就**不出**，并且出一行"为什么不出的"记录：

```
1  锚点      —— 挂不上任何锚点 → no_anchor（音效）/ no_trigger（花字）
2  风格许可  —— 该触发类型在这套源草稿里没出现过 → trigger_not_in_style
3  结构门槛  —— stress / bgm_beat 微切不算切点 → non_structural_cut
4  作用域    —— 静音段 / 口播句中 / 不允许的镜头类型 → silence_ban / midline_ban / shot_type_scope
5  密度      —— 全局最小间隔 / 同角色最小间隔 / 每分钟上限 / 同角色每分钟上限 → *_min_gap / *_max_per_min
```

同时挂上多个锚点时按**语义强度**取一个：`cut`（画面换了）> `flower`（字上屏了）> `line`（换句了）> `beat`（踩拍了）。
一条 cue 只记一个理由，避免"什么都能解释"。

**密度不是常数，24 套各不同**，全部取源草稿实测：全片每分钟上限、同角色最小间隔（取实测值 ×0.6，
因为真值里那是两三条 cue 的极端值）、每角色的每分钟上限。

原则收束成三句话：

1. **说不出理由的不出。** 这是硬约束，不是扣分项。
2. **理由来自画面/人声的变化，不来自"该响了"。** 切点、换句、花字上屏、踩拍都是可观测变化；
   "这里该来一声了"不是。
3. **密度只能往下收，不能往上补。** 策略允许比源草稿更干净（最低到 35%），但绝不允许更密。

## 三、作用域（在哪能响 / 能上屏）

| 维度 | 音效 | 花字 |
|---|---|---|
| 镜头类型 | `scope.allowed_shot_types`（源草稿里 ≥10% 落在哪种镜头上就允许哪种） | 同左 |
| 纯静音段 | `scope.silence_ban`：源草稿里 ≥15% 的音效落在静音段才允许（实测只有综艺型风格会） | 一律禁（没有人声托着就没有出处） |
| 口播句中 | `scope.midline_ban`：句内且离句首 >0.25s、又不贴任何锚点 → 禁 | 只在句首/切点上屏 |
| 位置分区 | — | `scope.zones`：源草稿的 top/middle/bottom 分布 |
| 字数 | — | `chars_min~chars_max`（源草稿实测，如 style_21 是 1~5 字） |
| 停留 | — | `hold_sec_min~max`（源草稿文案块停留，夹在 1.0~6.0s） |
| 版式/配色 | 只能播本风格目录 `assets/sound_vibe/sfx/<style_id>/` 的真音效，**禁止跨风格** | 配色取 `multi_zone_flower_spec` 实测色，且必须过 4.5:1 对比度 |

## 四、可印证指标（复用后怎么证明「这就是这套风格」）

`scripts/style_fingerprint.py` 把每套风格做成可测指纹，`verify()` 拿实际产物逐项对：

| 指标 | 判据 | 为什么它能证明风格 |
|---|---|---|
| `sfx_per_min` | 源草稿 × [0.35, 1.10] | 每分多少次是这套风格的"呼吸频率" |
| `sfx_trigger_mix` | 主触发类型占比偏差 ≤ 0.25 | 音效是按什么理由响的（切点派 vs 花字派 vs 拍点派） |
| `sfx_trigger_known` | 不出现该风格清单外的触发 | 出现 `beat` 却是一套纯切点风格 = 套错了 |
| `sfx_role_mix` | 余弦 ≥ 0.60 | 音色角色配比（cut/accent/info/hook） |
| `sfx_min_gap` | ≥ 源草稿 × 0.6 | 有没有"连击"式堆叠 |
| `sfx_source_dir` | 99% 以上来自 `sfx/<style_id>/` | 跨风格串味当场露馅 |
| `flower_per_min` | 源草稿 × [0.20, 1.20] | 花字上屏频率 |
| `flower_trigger_known` | 触发类型在本套清单内 | 花字是不是按这套风格的时机上屏 |
| `flower_chars` | ≤ 源草稿上限 + 3 | 短标 vs 长句是风格的一部分 |
| `flower_palette` | 源草稿主色/描边色出现在成片 | 配色是最强的肉眼辨识项 |
| `bgm_bpm` | 与源草稿 BPM 相差 ≤ 4% | BGM 不是这套的曲子一眼就穿 |

`verify()` 还会用可测特征反推**最像哪套风格**（`style_guess`），声明的风格不在第一名就判 FAIL——
这就是"套错风格能当场看出来"。

## 六、溯源方法与已知局限

- **切点/换行**：`style_edit_grammar.json` 的 `main_segments` 与 `text_beats`。
- **花字起止**：`draft_content.json` 里除字幕轨之外的所有 `text` 轨段（字幕轨由 `text_beats.subtitle_track_index` 指定）。
- **BGM 节拍**：源草稿的 `beats` 材料不带时间戳（`ai_beats.melody_percents` 全是 0），只能从本风格
  BGM 音频做自相关估 BPM（多窗互证，置信度 <0.45 时**禁用** beat 作为理由）。style_21 估出 99.38，
  与 pipeline `03_audio_events.json` 里 librosa 的 99.4 一致。
- **style_01** 的明文草稿落盘名是 `__latest_close.json`（无 `draft_content.json`）。
- **归因不上的部分不假装**：`card`（文字面板）/`fragment`（单字碎片）/`free`（编辑改写）记录在
  `evidence.unexecutable_share`，pipeline 不去生成这些内容。
- **花字可归因率低于 0.6 的 4 套**（style_03/08/15/17 附近）在 `evidence.note` 里写明"编辑改写/与字幕
  不同源"，提示这不是策略漏判。

# ③ 核对这次成片是不是这套风格
python3 short-video-studio/scripts/style_fingerprint.py --style style_21 --pipeline-dir <pipeline>

# ④ 回归测试
python -m unittest discover -s tests
